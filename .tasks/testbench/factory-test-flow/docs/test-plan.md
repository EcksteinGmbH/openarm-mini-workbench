## 0. 原则

1. **官方流程是骨架**：官方只有 7 步（BOM/打印 → 装 LeRobot → 装配前写 ID → 10 步装配 → 找串口 → 校准 → 遥操作），
   本方案每个阶段都标明对应的官方步骤；本地加的闸门不得改变官方步骤的结果。
2. **官方没有任何 leader 验收判据**。所有数值判据都是本地判据，每条写明依据类型：
   `官方`（硬件 README / LeRobot 源码）、`规格`（Feetech 规格书）、`推导`（由前两者推出）、`待定标`（先记录，首批实测后定数）。
   推不出的不编数字（沿用 OpenARM `derived-thresholds.md` 的做法）。
3. **全程不上扭矩**。写入只有三处：第 1 阶段的 ID/波特率、官方 `lerobot-calibrate` 自己写的校准参数、
   官方驱动 `connect()` 时自己写的运行期配置。
4. **判定在服务端**，每一项判定结果写入会话日志；报告只从日志生成。
   **必做项缺记录 → 不能出 PASS**（SO-ARM101 前端判定导致三台 Leader 归档缺质检项仍写"通过"，不重蹈）。
5. **结论三态**：`PASS` / `HOLD`（有警告或缺项，需处置或重测）/ `FAIL`（有失败项）。
6. **可追溯**：报告写明工作站版本、LeRobot 版本与来源、判据表版本、电源档位、操作员。

## 2. 各阶段内容与判据

### S0 工位与来料确认

| 项 | 判据 | 依据 |
|---|---|---|
| 串口适配器 | 恰好 1 个，`/dev/serial/by-id` 别名可读写（`dialout`） | 推导（现有实现） |
| 串口未被占用 | `lsof` 无其他进程 | 推导（SO `id-scan-failure-causes`：72% ID 失败是物理/工位原因） |
| LeRobot | 解析到的可执行文件为单臂代 `openarm_mini`；记录版本与来源 | 官方（驱动代见 wiki） |
| Waveshare 跳线 | 在 B 档（人工确认） | 官方（SO-101 排障说明） |
| 来料 | 8× STS3215-C046（7.4 V），打印件 16 件，夹爪件 L/R 与编号侧一致（人工勾选） | 官方（BOM） |
| 电源设定 | 与所选档位一致（人工确认 + S1/S3 实测复核） | 官方（BOM 7.5 V ≥2 A） |
| **台架夹具** | 整臂可固定在竖直立柱上自由下垂（同官方照片 `images/openarm-mini1.jpg`），S3–S6 均在此姿态下做 | 官方（零位定义为整臂下垂；照片中的安装方式） |

### S1 电机预配置 ×8（装配前，顺序 8 → 1，总线只接一颗）

保留现有四步（广播扫描 → 写 ID+1 Mbps → 断电 5 s 复扫 → 只读反馈），补两项只读基线：

| 项 | 判据 | 依据 |
|---|---|---|
| 单颗在线 | 广播只有 1 个应答，型号 777 | 官方（`_find_single_motor_p0`）+ 本地多应答闸 |
| 电压 | \|实测 − 档位\| ≤ 1.0 V，且 ≤ 7.4 V + 1.0 V | 推导（现有，实测稳态偏差 ~0.3 V） |
| 写入持久 | 断电 ≥5 s 后以新 ID、1 Mbps 复扫到同一型号 | 推导（ID/波特率在 EEPROM；官方新版只做当次 ping） |
| **固件版本**（新） | 读 `Firmware_Major/Minor`（地址 0/1）记录；S3 判 8 颗一致 | 官方（LeRobot 连接时校验固件一致，不一致报错） |
| **保护限值**（新） | 读 `Max_Temperature_Limit`(13)、`Max/Min_Voltage_Limit`(14/15) 记录 | 待定标（规格书过压阈值 7.4 V 与 BOM 7.5 V 电源的关系须实测确认） |
| 反馈连续性 | 手转舵盘，展开后跨度 ≥ **待定标**（建议 1024 计数 = 90°），无非接缝跳变 | 待定标（现阈值 100 计数过低，实测 283–2327） |

### S2 装配与装配检查（人工勾选，逐项入日志）

按官方 10 步装配。检查表（腕带佩戴参照官方照片 `images/openarm-mini2.jpg`）：M2/M3 螺丝齐全拧紧、8 个舵盘与舵盘螺丝、菊花链 1→8 线序、
全行程摆动时线缆不受拉扯不被夹、夹爪扳机回位、腕带装好可调、Waveshare 板固定。
任一项未勾选 → 不能进入 S3。

### S3 整臂电气与通信（只读）

| 项 | 判据 | 依据 |
|---|---|---|
| 完整性 | ID 1–8 全部应答，型号 777 | 官方（电机表） |
| 固件一致 | 8 颗 `Firmware_Major/Minor` 相同 | 官方 |
| 电压 | 每颗 \|实测 − 7.5\| ≤ 1.0 V；8 颗极差 ≤ 0.3 V | 推导 / 待定标（极差项） |
| 温度 | 静止、未上扭矩时 ≤ 40 °C | 推导（规格工作上限 60 °C、70 °C 关扭矩；实测静止 27–29 °C） |
| 状态 | `Status` == 0 | 推导（Feetech 状态位为告警位） |
| 扭矩 | `Torque_Enable` == 0 | 本地原则（全程只读） |
| 出厂配置 | 记录 `Phase`、`Max_Acceleration`、PID、保护电流等；不判（校准/连接时官方会重写） | 官方（实测出厂 `Phase=92`、`Max_Acc=250`） |
| **通信稳定**（新） | 连续 60 s 同步读 8 颗位置，0 失败 | 本地（SO R03 增强复测用 600 s，此处取标准档） |

### S4 关节身份与活动性（只读，新增）

逐个提示"只动 Jn，走完它的机械行程"，同时采 8 颗位置：

| 项 | 判据 | 依据 |
|---|---|---|
| 身份 | 跨度最大的电机就是 ID n，且 ≥ 其余任一电机跨度的 3 倍 | 推导（抓装错位/接错线的电机；ID 6/7 的软件对调由驱动处理，物理上必须 ID6=J6） |
| 活动性 | 展开跨度 ≥ 该关节**待定标**下限 | 待定标（首批 3 台建基线；基线只用于发现变化，不当规范） |
| 连续性 | 采样间无非接缝跳变 | 推导（编码器读数连续） |
| 夹爪 | 闭合↔张开跨度 ≥ **待定标** | 待定标 |

### S5 官方校准与一致性核对

| 项 | 判据 | 依据 |
|---|---|---|
| 预检 | 8/8：读数 ≤ 4095，折算偏移 \|actual − 2047\| ≤ 2047（`mod 4096`） | 官方（偏移寄存器 11 位） |
| 校准完成 | 输出含保存标记；沿用旧文件提示一律回答 `c`；退出码 0 无标记 = `finished_unsaved` → FAIL | 官方（提示串）+ 本地 |
| 核对 #1 | 文件 vs EEPROM：`Homing_Offset`/`Min`/`Max` 一致；`Phase`=12；J1–J7 量程 0..4095 | 官方 |
| 核对 #2 | 断电 ≥5 s 后重复核对 #1 | 推导（EEPROM 持久） |
| 运行期字段 | `Acceleration` 断电归零只提示 | 官方（SRAM，连接时重写） |
| 夹爪量程 | `range_max − range_min` ≥ **待定标**；记录 `drive_mode` | 待定标 |

### S6 官方驱动读数验证（leader 侧，新增）

官方第 7 步 `lerobot-teleoperate` **必须**带 `--robot.*`（`TeleoperateConfig.robot` 必填），没有 follower 跑不了；
README 里的命令是 8d150667 删掉 `so101_follower` 后留下的残缺版本。
这里用同一个官方驱动只做 leader 半边：在 LeRobot 环境里以 `OpenArmMini(side=<L/R>)` `connect(calibrate=False)`，
循环 `get_action()`。`configure()` 先关扭矩，只写官方运行期配置，与客户遥操作时完全相同。

| 项 | 判据 | 依据 |
|---|---|---|
| 驱动接受校准文件 | `is_calibrated` 为真，不弹校准提示 | 官方 |
| 零位读数 | 整臂下垂、夹爪闭合：J1–J7 \|pos\| ≤ **待定标**（建议 5°），夹爪 ≈ 0° | 推导（零位即校准姿态） |
| 夹爪映射 | 闭合 ≈ 0°，张开 ≈ −65°（容差待定标） | 官方（`GRIPPER_TELEOP_TO_DEGREES = −0.65`，follower 夹爪 −65..0°） |
| 方向 | 按方向表逐关节正向摆动，读数符号与表一致 | **待定标**：方向表需用一台 follower 或官方机械约定建立一次 |
| 侧别 | 运行时传入的 `side` 与编号 L/R 一致；生成的交付命令含 `--teleop.side` | 官方（B3） |
| 6/7 对调 | 动 J6 时 `joint_7.pos` 变化，反之亦然 | 官方（`JOINT_REMAP`） |

### S7 与 follower 遥操作配对（可选）

完整官方第 7 步：`lerobot-teleoperate --robot.type=openarm_follower --robot.port=can0 --robot.side=… --teleop.type=openarm_mini --teleop.port=… --teleop.side=… --teleop.id=…`。
需要 OpenArm follower（达妙 CAN，见 OpenARM 工站）。不做时在报告"未验证项"中写明，不得解释为通过。

### S8 增强复测（可选，沿用 SO R03 模板）

静态通信 600 s / 0 失败；动态通信 300 s / 0 失败且 8 轴均有变化；电源循环 3 次 3/3 恢复；USB 重新枚举后 8/8 应答且校准一致。

### S9 终检、归档与放行

- 断电外观检查（人工勾选）、贴编号。
- 自动生成归档 `test_reports/Leader/<编号>/`：`<编号>_OpenArmMini_基础测试记录.{md,pdf}`、`_校准参数.json`、`_会话日志.jsonl`；
  文档号 `OAM-{L|R}-BENCH-RESULT-<编号>-R01`；复测递增 `R02…`，旧版不删。
- 报告章节沿用 SO 基础测试记录：头部信息 → S1 → S2 → S3 → S4 → S5 → S6 → 异常与限定项 → 未验证项与边界。
- **放行门**：所有必做阶段有记录且 PASS、无未处置警告 → `PASS`；否则 `HOLD`/`FAIL`。签核：测试员 + 复核人（具名）。
- 编号索引 `test_reports/编号与归档索引.md` 追加一行；作废号不复用。

## 3. 判据管理

- 所有阈值集中在一张判据表（代码常量 + 文档），带 `id`、数值、依据类型、来源；报告打印判据表版本。
- `待定标` 项在定标前只记录、在报告中标"记录项"，不参与 PASS/FAIL；定标后升级为判据并记 CHANGELOG。
- 定标方法：首批 3 台完整跑 S1–S6，取实测分布定下限，写进 `agent_wiki` 的 decision 页。
